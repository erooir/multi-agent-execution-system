# 新任务能力接入路径

平台已有技能包、HTTP工具、MCP服务和原生工具集四种扩展接口。扩展先成为版本化能力，再由智能体明确授权使用，任务受理时冻结绑定。

## 按能力选择接入方式

| 新能力 | 建议方式 | 主要工作 |
| --- | --- | --- |
| 阅读步骤、领域术语和报告写法 | 技能文档包 | 提供SKILL.md和references文本，导入并发布，绑定已授权工具 |
| 已有内网OCR、语义检索、图谱查询或媒体分析服务 | HTTP工具 | 约定JSON输入输出，配置主机白名单和服务端密钥引用，登记并发布 |
| 已有标准工具服务 | MCP | 管理员预配置启动器或服务地址，发现工具，检查参数结构后发布 |
| 已有Agno工具集 | 原生工具集 | 当前工厂支持calculator和duckduckgo；新增工厂需研发接入并验证 |
| 全新的业务任务类型或领域算法 | 研发扩展 | 增加输入输出契约、执行器、质量检查和样例；再纳入能力目录 |

扩展页面支持登记与发布。发布后在智能体中选择能力，再发布智能体版本；修改已发布工作流时同样发布新版本。旧任务继续使用冻结配置。停用、撤销和来源有效性检查由后端执行。

## 多模态服务的约定

HTTP工具当前发送JSON并校验JSON结果。二进制媒体先登记为资料，由适配器按授权读取；现有接口不提供任意文件路径或自动将原件发送给第三方的机制。接入新的媒体服务时，需要明确资料传递方式、大小限制、时间码或图像位置、错误码和来源回传。

现有外部工具只接入只读且不按次计费的服务；付费模型走统一模型网关。运行时不安装插件依赖、不执行技能包脚本。新增工具的可执行代码通过正常研发发布，技能文档只表达方法和参考内容。

## 每次接入的最小验证

使用合成资料验证正常结果、参数错误、越权资料、来源撤回、超时和返回结构变化。检查任务中能看到真实调用记录、来源与版本。随后用独立业务样例验证结果质量，验证通过后再扩大智能体授权。

完整接口和字段见 `INTEGRATION.md` 与 `contracts`。本平台的扩展包遵循自身契约，借鉴模块化设计，无需替换执行引擎。
