## 视觉与信息层级

- 浅灰画布、白色面板、紫蓝主色；统一按钮、输入、表格、弹窗、状态和键盘焦点。登录、问答、任务图与流程编辑画布均使用 Light 样式。

## 变更边界

不修改后端、数据库结构、API 路径、Page ID、状态枚举、任务请求值、轮询节奏、权限、工具授权、模型网关或费用账本。新增/调整的交互仅为说明展开、页面布局和 Light 画布呈现；不修改默认表单值或执行方式。

`styles.css` 提供统一语义颜色，`light-workspace.css` 提供 Light 布局与组件外观。主题完全使用本地 CSS 和已有图标，无 CDN、外部字体或新增包。

## 验证

使用独立离线服务和明确标注的合成资料验证；真实业务资料、密钥、截图和运行数据库均不提交。新增浏览器检查覆盖 11 个管理模块、登录、问答、表单说明、Light 执行图及 390px 移动布局。原业务流程测试仅同步 UI 名称和统计展开操作，保留原 API、产物、权限和状态断言。

结果：前端单元 31 项通过，浏览器 11 条不同流程通过，2 条真实云调用流程未执行；生产构建和修改文件的格式检查通过。AST 对比核验 15 个修改的 TSX 文件，其 API 调用、请求参数、状态默认值和 effect/callback 未变。测试账号触发登录限频时等待原窗口恢复，不修改鉴权。截图仅保存在忽略的 `.local/light-screens/`。
