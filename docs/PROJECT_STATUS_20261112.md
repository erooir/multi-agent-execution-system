# 航智智能体管理平台建设现状与后续任务

更新日期：2026年11月12日。核对范围为最新项目 `multi-agent-execution-system-cloud-adapt`、两份重建方案、自制案例资料和年度目标图片。

## 一 项目已经形成什么

项目已经形成以智能体资产管理为中心的平台原型。用户提出问题或提交任务，平台在项目授权范围内选择资料与能力，组织执行流程，调用工具或模型，检查结果，必要时自动修订，最后交付结果和来源依据。管理员可以管理智能体、版本、流程、资料、扩展能力和运行记录。

当前已经超过单一报告演示的阶段，具备资料整理、结构化计算、文档分析、图像文字识别、音视频处理和地理时序分析等任务入口。主要建设重点已经转到业务材料覆盖、检索与模型接入、流程能力补齐和量化验收。

三类场景各有10个案例，共30个案例流程。用例协作组包含30个分析岗位、1个共享解析岗位和1个共享核查岗位，共32个；项目还可另行发布通用智能体。30个分析岗位对应26类主处理算法，同类岗位复用算法并分别约定输入、产物和审核条件。

技术上采用自建网页管理台、Python服务、Agno智能体运行框架和独立任务执行进程。当前正式启动路径使用达梦数据库；两份方案中提出的PostgreSQL属于早期选型，代码仍保留相关适配与测试。这是架构实现中的实际调整。若最终交付仍要求数据库也全部开源，需要确定数据库交付选型及许可证要求。

### 智能体协作与上下文追溯

## 六 智能体如何管理及运行

### 三个对象分别管理

智能体定义描述“这个岗位负责什么”，包含用途、能力、模态、指令、允许工具、模型策略及复合成员。发布版本描述“当时采用哪套配置”，发布后保留不可变副本。运行实例描述“这次由谁执行”，绑定任务和版本，并具有独立上下文与运行状态。

通用与专用是用途分类。当前32个用例岗位采用独立的元智能体定义，通过工作流建立依赖关系。平台代码另有复合定义和成员配置能力，发布时检查循环引用、嵌套深度、版本及工具权限；当前案例采用的是独立岗位组成流程的方式。

### 定义的生命周期

创建草稿后可编辑配置，校验通过即可发布。发布版本供新任务选择；修改后再次发布生成新版本。停用阻止新的任务使用，已有任务按受理时冻结的版本继续执行。退役后退出正常使用。销毁采用保留历史的逻辑处理，并检查流程、成员和运行引用。

### 实例的生命周期

任务先登记并校验，再由执行进程领取，进入规划、执行和审核。节点开始时建立实例，完成后释放；进程接管时保留旧实例异常记录。任务最终进入成功、部分完成、失败或取消。执行进程利用租约、心跳和递增令牌控制写入，避免过期执行者覆盖接管后的结果。

### 上下文与协作

原有上下文管理包含以下几个层次：

1. **固定本次任务的依据。** 任务受理时保存资料、智能体和流程的版本快照，执行期间据此检查权限、资料有效性和内容完整性。各节点共享本任务的授权资料范围，工具调用仍需逐次检查；当前案例没有额外按岗位拆分原始资料权限。
2. **按依赖传递结果。** 执行器将已完成结果放在本任务的节点结果集合中，按流程依赖选择上游结果交给下一节点。解析结果包含记录和资料缺口；分析结果包含产品、证据和缺口；核查节点同时读取两者。无依赖关系的分支不会自动收到对方的输出。
3. **分别组织模型输入。** 每次工具型模型执行创建新的智能体对象，并关闭自动附带历史会话。普通文本路径显式组织目标、来源、上游结果和修订问题；云端案例路径主要传入资料目录、上游结果摘要、修复计划和产物引用，完整中间结果保存在后端，供本阶段工具读取。本地案例直接在程序中传递结构化结果。
4. **保存执行记录并恢复。** 每次实际节点执行建立运行实例和上下文编号，输出与状态持久化。修订或恢复时，按规则复用成功检查点，其余节点重新执行。上下文编号用于关联记录，隔离还依赖任务级数据范围、新建执行对象和后端权限检查。
5. **单独管理长期记忆。** 长期记忆保存带来源和期限的获准片段，查询时检查项目权限和来源有效性。来源撤回或过期后，关联记忆失效。

本轮新增的清单将结果交接对应到真实节点与结果指纹。管理员可以查看“哪个步骤的结果交给哪个步骤”“使用哪个版本”“是否沿用上轮结果”。它记录执行器收到的上游产物来源，具体模型输入仍由各执行路径组织。通用的上下文长度预算、自动压缩、节点级资料裁剪和消息收发协议尚待建设。

## 七 上下游输入输出约定

### 建议的对接方式

上游先登记资料，获得平台资料编号；下游提交任务目标和资料编号；平台返回任务编号；下游查询状态或订阅事件，结束后获取结果包并下载产物。这样大文件只需登记一次，多次任务均能引用明确的资料版本。

资料至少说明所属项目、名称、模态、媒体类型、内容或文件、来源标识、来源版本以及来源授权说明。平台计算内容校验值并记录有效期。云端处理需要公开分类和相应授权，未获外发授权的资料走本地处理。

| 数据类型 | 当前接收方式 | 上游应一并提供 |
| --- | --- | --- |
| 文本与记录 | UTF-8文本；JSON对象数组或records对象；JSONL、带表头CSV按相应任务入口解析 | 稳定编号、字段说明、日期时区、单位、来源版本 |
| 文档与工作簿 | 用例解析支持PDF、DOCX、XLSX等原件 | 页码、工作表、表头；跨版本任务明确前后版本，扫描件保留原图 |
| 图像 | PNG、JPEG等已支持格式；OCR与语义理解分别选择能力 | 尺寸、拍摄或观测时间、来源；地理图像另提供空间范围和坐标系 |
| 音频与视频 | 通过媒体上传及已配置的解码、转写组件处理；也支持带时间码字幕等配套材料 | 格式、时长、语言、时间轴、字幕与原媒体对应关系 |
| 地理与时序 | 案例约定的结构化记录、空间要素、栅格或序列表 | 坐标系、单位、时间范围、缺失值、分类含义、基线与对照资料 |

通用数据封装统一，业务字段按案例分别约定。例如G03海冰案例需要明确年份、月份、数值和基线范围；条款对照需要两个版本和对应关系；道路分析需要有方向的路网、起终点和通行信息。登记为“文件”之后，还需满足所选任务的数据要求。

当前内联内容上限为2,000,000字节，一般文件为10,000,000字节，指定音视频为128,000,000字节，图片还受像素限制。JSON、CSV尽量使用UTF-8；大材料按来源、区域或时间窗分批，并保留完整批次范围说明。

### 下游任务请求

管理任务通常提供项目、任务名称、目标、任务类型、输入资料编号和幂等键；可指定工作流、本地或云端模式、截止时间、费用上限、最多修订次数、是否接收部分结果和质量规则。案例任务另提供案例编号。问答入口则接收项目、自然语言问题和幂等键，由平台匹配资料和任务。

同一幂等键和相同内容返回已有任务；同一键配不同内容返回冲突。调用方重试提交时应沿用原键，明确创建新任务时再换新键。

### 平台交付内容

结果包包含任务编号、最终状态、结束原因、产物目录、质量判断、缺口与提示、来源链、资源用量以及版本引用。任务未结束时返回进行中状态。下游分别处理成功、部分完成、失败和取消。

产物按任务提供结构化JSON、文本、CSV表格、图表或空间文件。案例可以导出包含中文简报、完整结果、证据清单和适用附属文件的成果包。来源撤回或过期后，平台保留追溯标识，并停止提供关联派生内容。

现有接口使用 `/api/v2` 前缀，数据、任务、结果及工具的结构定义保存在 `docs/contracts`。对接方先参考 `docs/INTEGRATION.md`，以结构定义编写请求校验。下游主动查询和事件订阅已经具备，主动回调接收地址、签名与重试协议仍需建设。
