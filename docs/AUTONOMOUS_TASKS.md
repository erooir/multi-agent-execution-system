# 自主任务入口与资料接口

本页说明 `codex/autonomous-task-platform` 分支。基线为 `main f36f490`，本期使用原有顺序 Worker，不引入并发分支。部署架构以 [ARCHITECTURE.md](ARCHITECTURE.md) 为准。

## 使用者需要做什么

1. 在根路径创建任务，描述问题与期望交付物；不必知道案例编号、智能体、工具或执行器。
2. 查看平台提出的资料需求，上传资料、选用已有授权资产，或让甲方系统通过本任务的资料接口提交。资料可以是原始 PDF、Office 文档、图片、音频、视频或结构化文件，不要求甲方先建立向量库。
3. 平台检查真实文件内容及格式，资料具备后规划并执行。无需资料的创作或方法说明允许不上传。事实性问题缺少证据时会返回具体缺口，不能凭空生成数据。
4. 查看结果、原件引用和未解决项。模型/工具、脚本版本、审核及流程变更在运行详情中可追溯，普通使用过程不要求用户配置这些组件。

云端任务的授权覆盖任务描述和所选公开资料。文件被标为“公开”并不自动授予云端访问；仅本地资料不能混入云端任务。部署仍可设置离线模式，但当前任意目标的模型规划需要已配置的模型；确定性本地分析与离线大模型推理是不同能力。

## 数据与执行的关系

| 记录 | 职责 |
| --- | --- |
| TaskCase | 用户的持续任务：目标、资料需求、提交批次、执行引用及累计额度 |
| DataSubmission | 一次逻辑提交：来源版本、资料关联、幂等键及内容检查 |
| PlanVersion | 不可变的步骤、智能体与工具绑定、输入校验值、变更原因 |
| TaskRun | 原有权威执行状态：租约、取消、节点、模型预算、产物与终态 |
| AgentCandidate | 从成功任务提取的工具/技能组合及独立评测证据 |
| ScriptVersion / SandboxRun | 实际生成的脚本、不可变哈希、运行限制、输出与状态 |

等待资料时释放 Worker。补充资料仍属于同一 TaskCase；既有执行、计划、失败记录及费用不被覆盖。每次新执行的可用费用扣除本任务先前的已结算费用和未决预留，全项目继续使用原历史账本的 300 元累计限制。

任务专属资料不会自动进入其他用户的任务或知识库。引用下载重新检查本人/项目权限、来源有效性和校验值；来源撤回或过期后，相关交付内容受到屏蔽。API 凭据只允许给指定任务提交资料，不允许读取答案、管理资产或执行任意工具。

## 接入接口

接口前缀为 `/api/v2`。交互式网页使用原有登录会话和同源规则；甲方系统使用针对单个任务、可过期和撤销的 Bearer token。

| 请求 | 用途 |
| --- | --- |
| `POST /task-cases` | 创建任务；提供 `project_id`、`goal`、`idempotency_key`，可补交付要求与额度 |
| `GET /task-cases?project_id=…` | 本人的任务列表 |
| `GET /task-cases/{id}` | 资料需求、进展、计划、结果、审核与轨迹 |
| `POST /task-cases/{id}/upload` | 网页 multipart 文件上传 |
| `POST /task-cases/{id}/submissions` | 关联已有授权资料；包含 `input_refs` 与幂等键 |
| `POST /task-cases/{id}/ingest-tokens` | 创建有期限的单任务资料提交凭据 |
| `DELETE /task-cases/{id}/ingest-tokens/{token}` | 撤销提交凭据 |
| `POST /task-cases/{id}/ingest` | 甲方 API 提交 JSON、CSV 或文本内容 |
| `POST /task-cases/{id}/ingest/upload` | 甲方 API 提交多模态文件，接口契约与网页上传一致 |
| `POST /task-cases/{id}/start` | 幂等地继续或启动当前任务 |
| `POST /task-cases/{id}/cancel` | 取消当前执行；已经发生的请求仍按实记账 |
| `GET /task-cases/{id}/result/download` | 下载当前可见的结果与审核 JSON |
| `GET /task-cases/{id}/sources/{asset}/download` | 下载授权原件；PDF 引用附带页码定位 |

JSON 提交示例（合成数据，token 从环境或密钥存储读取）：

```json
{
  "name": "部门经营明细",
  "content": [{"department": "甲", "revenue": 1000, "cost": 400}],
  "media_type": "application/json",
  "classification": "public",
  "source_id": "synthetic-departments",
  "source_version": "1",
  "provenance": "联调专用合成数据",
  "idempotency_key": "batch-001"
}
```

同一键、同一内容重试只产生一批提交；同一键换内容拒绝。可以在结果形成后重试已经成功的上传，不能借重试更改已冻结输入。生产凭据不能写入前端源码、Git、演示截图或说明文档。

## 自动审核与有针对性的修订

通用流程由模型根据目标、资料概要、可用工具/技能及已评测资产制定。每步拥有任务级冻结定义，最终交付另作确定性检查与独立上下文的模型评审。独立上下文不等于独立模型，相关偏差仍可能存在。

审核失败后，模型收到具体失败项和真实上轮结果，修改步骤、方法或工具形成新的计划版本；完全相同的计划不允许当作改进再次运行。原有 30 个领域案例保留可复算的专用修复策略，例如 B05 从正文解析切换到图表 OCR，然后重新计算和审核。预算、修订次数与截止时间共同限制迭代；未解决项以部分交付或失败明确结束。

脚本在 [SCRIPT_SANDBOX.md](SCRIPT_SANDBOX.md) 所述隔离环境内执行。容器成功退出只代表代码运行完成，不代表业务结果通过审核。展示真实代码哈希、执行限制、标准输出、错误及文件校验值；失败代码不得为成功结论提供依据。

## 新智能体如何成为可复用资产

成功的通用任务可提取候选流程，候选只保留工具/技能组合，移除任务原文、来源、答案与任务专属指令。原任务交付不依赖候选评测结束。

管理人员可以为候选启动独立评测。至少两个与来源任务不同的样本分别用于开发和留出，每个样本通过原 Worker 实际运行基线与候选，禁止拿来源任务的成功作为泛化证据。具有真实冻结执行计划和节点输出的失败任务可以作为难例；只有需求分析或初始规划失败的任务不能充当可执行基线。审核、费用完整性、费用回归及实际质量或费用改善共同决定能否入库；未通过不可晋升。通过后的资产可由后续任务规划复用。当前评测与入库由管理入口触发，不代表已经自动构造了高质量独立评测集。

## 验证边界

30 个预设案例保留领域合同与回归覆盖，但合同测试、模型替身测试、真实模型执行和真实公开原件验收需要分别记录。一次 B05 演示不证明所有复杂任务均能正确解决。工具依赖“就绪”表示本机依赖检测通过，不保证任何资料都能被准确识别；OCR、ASR、模型审核和复杂数值分析都须保留来源与未解决项。
