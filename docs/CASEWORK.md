# 用例研判：数据、运行与验收

适用版本：2026-11-02。平台按用例冻结项目资料、智能体版本、工作流、算法和本地工具，在达梦 DM8 中记录执行。**30 个入口可执行，不等于 30 组完整业务原件已经通过验收。** 看结论时须同时核对任务范围、终态、未通过检查和来源。

## 从安装到交付

1. 按[达梦部署与迁移](DAMENG.md)启动 API 和独立 Worker，确认当前项目可见且 Worker 在线。按[依赖与离线交付](DEPENDENCIES.md)预配需要的词库和模型。案例运行无需云模型或 API 密钥。
2. 在“用例研判”选择“安装项目协作组”。安装只发布版本化定义，不生成任务或观察数据。每个用例由资料解析员、对应专业分析员、独立核查员组成工作流。项目成员只能读写获准的项目；只读成员不能安装或提交。
3. 在“数据资料”登记原件及配套记录，填写资料来源、来源版本、出处、分类和保留期限；“用例研判”按 B/T/G 选择卡片，查看输入字段与交付契约，创建任务并选择输入。明确选择 **缩小样本验证** 或 **参考用例的指定批次**。先预检再提交；预检的 ready 表示能受理，警告或缺资料仍可能导致部分完成或失败。
4. 在任务详情看阶段、节点尝试、使用的智能体版本、审核和修订；在“用例研判 → 智能体运行监测”查看实际执行次数、失败、审核未过及耗时。每个实例独立释放。若冻结合同或工具发生变化，应保留原任务记录，按新版本重新受理。
5. 打开用例报告，查看 products、evidence、gaps、review，以及适用时的机译阅读索引。下载 ZIP 含 brief.docx、report.json、evidence.csv 和附件 manifest；按实际产物另有 CSV、GeoJSON 或静态 SVG。范围、参考批次版本摘要、机器译注和未译原因随报告保留；样本包不能当作完整参考报告。资料撤回/过期后，服务端屏蔽派生内容及下载；此前已下载的副本需由接收方处理。

对应 API 在 `/api/v2` 下：`GET /casework/catalog?project_id=...` 查询当前契约；`POST /casework/install?project_id=...` 安装；`POST /tasks/preflight` 和 `POST /tasks` 使用同一 TaskRequest。用例指定 `task_type=case_analysis`、`case_id`、`case_scope=sample|reference`、`mode=local`、`input_refs` 和项目内幂等键。用 `GET /tasks/{id}/result` 轮询（未终结返回 202），`GET /tasks/{id}` 查完整节点与审核，`GET /artifacts/{id}/case-package` 下载报告。批量系统请读取机器终态，不要以 HTTP 200 或 ZIP 可下载推定成功。

**可选的公开资料语义取证**是独立任务。当前默认开发入口允许该能力，后续离线部署可通过 `-Offline` 关闭。在线时按任务授权，只接受同项目明确可外发的公开文本/结构化资料（最多 12 份，单任务预算大于 0 且不超过 0.8 元）。若关联原用例，所有冻结来源须一致且都可外发，不能用公开子集代替原件。调用统一网关并沿用项目 300 元历史总账；下载成功任务的语义报告用 `GET /tasks/{id}/semantic-evidence/report`。科学文献可用“术语与测量复核”并列原文、中文读法及测量/模型口径。模型输出、独立评审和可从原文直接核对的缩写释义分别记录。语义解释不改变原用例结论。

**任务内修订**由本次核查反馈驱动，最多两轮，修订历史可追溯。**跨任务改进**默认关闭（`HANGZHI_AUTO_IMPROVE=true` 才启用自动维护）。当前用例候选只可调整本地分析专员的受限策略；使用同一冻结流程、来源互不重叠的实际参考任务重放基线与候选。开发样本须有可测增益，保留样本须通过且不能回归，满足门槛才发布新版本并更新流程绑定。后续回滚依据可复现的基线/候选差异；不改权限、模型权重或已运行任务的快照。

B01 的 ZIP 附一页中文快报 `bulletin.docx`，T01 附一页阅读卡 `reading-card.docx`。两者的完整结果、来源、翻译状态和未采用的译注仍在 `report.json`。B05 可取月度 CSV 和趋势 SVG，空心标记为部分月份；G03 提供年度序列和趋势图。

## 上游数据与证据定位

| 输入 | 实际解析与定位 | 提供方应说明 |
| --- | --- | --- |
| TXT/Markdown、JSON/JSONL | 文本保存段号、起止字符；JSON 接受记录数组或含 records/segments 的对象，JSONL 一行一个对象；记录有行号。 | 文档角色、日期/时区、字段名、单位；来源 ID 与版本不可用文件名替代。 |
| CSV、XLSX | CSV 表头必须唯一非空、行列齐全；UTF-8 或显式选 Windows-1252。表头在首行时 CSV 第一条数据为第 2 行；XLSX 保留工作表名及实际行号。 | 不同记录类型用 kind 区分；字段字典用 target_source_id 绑定当前任务的具体资产。 |
| DOCX、PDF | DOCX 读取段号或表号/行号；PDF 读取页码，无文本页可用已配置的离线 OCR。图表识别仅对已实现的版式/标签工作。 | 页码和表号从 1 开始；版本顺序、统计口径和单位分别登记。加密 PDF 不受理解析。 |
| 图片、GeoJSON、栅格 | PNG 等图片读取实际像素。注记 bbox 为像素 [x,y,w,h]，应声明图像 ID、日期和坐标空间；GeoJSON 要素定位到记录行。空间计算要求显式 CRS、有效几何。网格给原点、像元大小、日期、有效性掩膜；面积/长度分析提供适用的米制坐标系。 | 原图、参考图库、已有人工观测和算法输出分列；缺坐标不得生成点位。几何的屏幕截图不能代替可计算的网格或矢量。 |
| 音频、视频、SRT/VTT | 带流的文件经本地探测；可解码视频帧、可用的本地语音转写片段分别按 frame_ms 或 start_ms/end_ms 定位；字幕按 cue 定位。 | 声明媒体 ID、时间基准、说话人或发言角色的出处。字幕本身不证明录音里说过相同的话；缺 ASR 权重会记录缺口。 |

提交前约束：单任务最多 50 份资料；内联值上限 2,000,000 字节。一般文件上限 10,000,000 字节，指定音视频上限 128,000,000 字节，图片上限 2,500 万像素。解析器限制每任务 60,000 条记录、文本/字段约 1,600 万字符，另有 PDF 页数及 Office 解压限制。大材料应按真实来源或时间窗分批，不应删行后仍称原批次。申请输入的 asset ID、source_version、内容 SHA-256 在受理时冻结；报告中的证据编号引用本任务的具体版本和位置。人工标注、机器翻译和推断都不能替代原文。

## 核实参考批次

`sample` 核对本次选入资料的证据、结构及规则，不证明覆盖指定业务范围。`reference` 除相同的领域审核，还核对部署方维护的可信来源清单和适用的范围条件。清单与项目上传区分离；普通 API 不接受申请者自行声明的“完整”清单。缺少可信清单、缺原件、错版本、重复或多带资料都会留下未通过检查；没有实质产物或引用不符不能报成功。

登记十组已知参考原件时，部署人员先核对供方 download_manifest.json 的文件名、字节数、SHA-256 和版本，保护私有目录并运行以下命令。代码只读取本机原件，不访问清单里的 URL。

```text
python -m scripts.register_reference_batches --materials <已核验原件目录> --scope project --project-id <项目ID> --version <清单版本>
```

默认注册表是忽略的 `.local/casework/reference-batches.json`；可用 `HANGZHI_REFERENCE_BATCHES_FILE` 指定私有部署位置。项目条目优先于显式登记的共享条目；`--scope public` 只表示批次规则共享，不改变项目资料的访问或外发权限。同版本不可替换内容；新版以 `--replace` 切换并留存清单历史。每次受理冻结所选条目及摘要；原任务复核不追随外部清单后续修改。可约定记录数、产品数、指定字段值集合；B06 只接受严格绑定两份已登记原件的前后版本配套记录。更换数据、范围或材料后，用新的任务幂等键重新验收。

## 本机验收证据与边界

以下结果来自两种不同的运行，不合计为“通过用例数”：

* **缩小样本**：在隔离的离线 DM8 服务上，使用可再分发的合成输入，经 HTTP 受理、真实 Worker 和审核，30 个用例均完成，付费请求 0。复跑使用 `python -m scripts.verify_casework_matrix --url http://127.0.0.1:8100 --output .local/case-validation/<新的输出文件>.json`；验收账号从私有环境取得，脚本拒绝正式 8000 端口。
* **原件首轮**：已核验的 11 份原件对应 10 组任务；B01、B05、G03 成功，B06、T01、T05、G04、G05、G06、G07 部分完成。该记录是一次具体输入/版本的结果；完善审核与译注后，须用新受理的参考任务复测。其余 20 项的工程样本不能代替缺少的原件。最新批次以[验收记录](VALIDATION.md)为准。

| 首轮部分结果 | 能交付的证据 | 完整业务验收仍缺什么 |
| --- | --- | --- |
| B06 / T01 | 条款对照或研究卡，以及可定位原文 | 部分条款/译注审查未过或阅读索引覆盖不足；保留未确认项 |
| T05 | 指定图号、能定位的图注/正文 | 部分数值缺少可核验标注；不得用柱高估读代替原值 |
| G04 / G05 / G06 | 报告中的背景段落及页码 | 仅背景 PDF 不能提供水体与道路几何、逐建筑前后观测、三期共同格网及验证像元 |
| G07 | 643 条窗口内化验记录、5 个样品/站点的质控统计 | 首轮缺可核验站点坐标等条件，未生成有效样点；不能据此宣称区域覆盖 |

复跑十组原件：先启动独立离线 DM8 服务与 Worker，准备可信清单（验收脚本会新建项目，使用适用于该项目的登记规则）。再运行 `python -m scripts.verify_case_batch --materials <原件目录> --url http://127.0.0.1:8100 --output .local/case-validation/<新目录>`。脚本核对原件哈希、实际终态、来源、报告 ZIP 与预算前后是否一致，产物留在私有目录；退出码 0 表示所选参考任务全部成功，2 表示存在真实未完成结论，1 表示验收执行错误。不要把基础设施错误改记成部分业务成功。

**时限分三种口径。** `deadline_seconds` 是从受理起算的执行截止时间，包含排队；超时记失败/原因，不保证在任意负载内交付。用例入口默认填写 1800 秒，十组原件验证脚本默认 600 秒，这些是运行配置。要验证业务要求的目标时限，应在指定硬件、完整材料及约定并发量下记录 accepted→finished 的端到端耗时、重试/修订和结果质量；仅达到时间但产物缺失，不能算通过。单机缩小样本和验收脚本等待上限不能作为生产 SLA。
