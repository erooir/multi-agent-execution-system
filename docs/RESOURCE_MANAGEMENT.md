# 资源计量与并发配置

管理页“资源计量”和 `GET /api/v2/resources?project_id=...` 按项目查询。接口要求管理员或有该项目权限的操作员、观察员。平台主机的物理内存及逻辑处理器数量只对管理员显示。未关联本项目任务的维护性调用不计入此项目统计，平台 300 元历史总账仍记录相应调用。

## 模型调用

每一轮真实 HTTP 请求均经过模型网关。同一工具循环中的多轮请求各自准入和计量。网关按请求序列化文本字节数、原有安全余量和图片预算得到保守输入上界，加上该请求的最大输出，检查是否超过部署窗口。上下文估算会高于实际 tokenizer 结果。页面展示的实报用量来自服务商返回的 prompt_tokens、completion_tokens。输入和生成之和是单次请求的 token 用量，不代表 GPU 的 KV 缓存占用量。

管理查询使用 SQLite 只读连接。即使旧账本没有资源附表或内网调用视图，也能读取该项目的历史费用和已确认 Token，缺失的窗口及耗时明确标为不可用。账本缺失、不可读或结构不兼容时页面显示不可用；查询不会创建或升级账本。实际网关派发仍要求可写且有效的原账本。

费用、预留和未知费用都沿用既有共享账本。resource_requests 附表只记录限额、预估与经过时间，以原 charge_id 对应，不记录请求正文。旧记录的实报 token 可用于历史统计；旧调用缺失预估、持续时间及当时窗口时不纳入对应指标。没有使用量的调用保留原预留并计入待确认。本地确定性任务没有模型 token；按照真实任务租约和终态时间单独统计。

模型请求时延为准入和费用预留成功后到网关处理响应结束的本机经过时间，包括最终失败的已派发请求，不含等待并发位置的时间。本地任务时长从首次执行租约到终态，包括有限修订；缺少有效时间戳的记录不参与时长统计。两个分布分别使用最近秩法 p50 / p95，页面同时展示样本数量。

## 部署配置

API 和 Worker 启动时使用相同的环境设置。修改限额时统一重启同一部署下的 API 和所有 Worker。

| 环境变量 | 默认值 | 范围与作用 |
| --- | ---: | --- |
| HANGZHI_TASK_SLOTS | 8 | 1–256，同一业务数据库中未过期的并行执行租约数；云端、本地及离线任务共享 |
| HANGZHI_MODEL_SLOTS | 2 | 1–64，同机共享同一历史账本路径的活动模型 HTTP 请求数 |
| HANGZHI_MODEL_QUEUE_SECONDS | 30 | 1–300，模型并发已满时最长等待时间，超时由既有有界恢复策略处理 |
| HANGZHI_CONTEXT_TOKENS | 1000000 | 1–1008000，单次提交前可接受的上下文预算。部署应按实际模型上下文能力设置 |

Worker 原有 `--concurrency` 继续控制单进程任务数。任务领取事务在业务数据库的现有单例行上加锁并检查全部活动租约，随后选取下一个已排序任务；进程退出后的失效租约沿用原恢复机制。模型网关使用历史账本同目录的 `<账本名>.slots/` 作为本机进程共享的槽位目录。进程持有对应 SQLite 文件的排他锁，进程退出由操作系统释放锁。运行中应保留该目录与文件。多台独立主机的模型槽位不共享；多机推理服务仍需要服务端统一准入。

## 客户硬件估算

先用目标模型、量化精度、上下文长度和多模态输入进行预热。记录同一内存池可供推理的容量、模型与服务常驻占用、代表性并发请求的峰值增量，单位均为 MiB。面板估算可容纳并发数为 `max(0, floor((扣除安全余量后的容量 - 常驻占用) / 每路峰值增量))`。客户设备和推理后端型号未配置时，容量输入留空。主机物理内存与推理设备显存分别核算。估算结果不会自动改动运行限额，需用客户任务实测吞吐量和时延后配置。

2026-11-18 本机开发样例（Windows，32 个逻辑 CPU，32478 MiB 主存）。使用临时 SQLite、离线模式与两个消费者；12 个独立的本地结构化处理任务各读取 100 条合成记录，经真实领取、Agno 执行、审核后均成功。任务入队后从开始消费到全部结束共 1.05 秒，约 11.4 个任务/秒；首次领取至终态 p50 为 155.3 毫秒，p95 为 183.7 毫秒。此样本只反映所述本地确定性工具，付费模型请求为 0。客户 GPU 的模型加载开销、长上下文、多模态显存、模型吞吐与并发仍待目标硬件测量。

## 可复核边界

`backend/tests/test_resource_management.py` 使用隔离账本与模拟 HTTP 响应验证上下文拒绝、历史与新调用汇总、未确认费用、项目隔离和本地耗时。独立子进程占满模型槽位后，另一个进程的调用会在派发和费用预留之前被阻止；占位进程退出后槽位恢复可用。任务端测试以多个竞争领取者验证并发上限与过期回收。

## 对接上游内网模型

部署管理员可为 API 和 Worker 同时配置以下环境变量，重启两个进程后生效。缺少配置或地址、凭据、计量方式不符合约束时，平台拒绝模型请求。任务正文和 API 请求不能设置网络目标。

| 配置项 | 含义 |
| --- | --- |
| HANGZHI_UPSTREAM_MODEL_URL | 固定的 OpenAI 兼容 base URL，例如 http://127.0.0.1:9000/v1。仅接受 IP 字面量。专用内网 IP 须使用 HTTPS，并通过证书校验；本机回环可用 HTTP。 |
| HANGZHI_UPSTREAM_MODEL_ID | 上游已加载模型的标识，响应中的 model 必须与之相同。 |
| HANGZHI_UPSTREAM_API_KEY | 上游独立凭据，只发送给绑定的端点。缺失时拒绝调用，不使用云端凭据代替。 |
| HANGZHI_UPSTREAM_BILLING | 仅接受 internal_zero，表示客户明确确认自托管服务不收取按请求费用。未核价的第三方付费服务不能使用此配置。 |

文本摘要、原生 Agno 工具型文本入口、独立复核共用同一模型客户端、项目授权、上下文和并发准入。已配置内部供应端时，模型执行仍使用既有“需模型”的 cloud 任务和公开资料授权策略，网络只指向配置端点的 /v1/chat/completions。强制离线开关仍关闭这条任务通路。工具循环取决于上游是否实现对应的工具调用协议；视觉等额外模态也需要供应端单独验收。

每次内网派发在 intranet_requests 单独登记 provider、模型、用途、任务及用量状态，原有 charges 表仍只记录付费调用。请求次数与 Token 的项目汇总同时覆盖两者，资源管理页单列内网次数。内网返回的 Token 数须为非负整数，缺少用量、模型名不符或通讯中断时标记该次未确认，不视为一次成功交付。零单价指财务结算，Token、窗口和并发准入照常生效。替换端点不增加项目可用资金，也不会清除原有未决费用。

2026-11-18 以真实回环 HTTP 服务做协议验证，服务返回显式的固定测试回复与固定 usage。正常平台文本任务通过 Agno SDK 发送摘要请求、保存来源引用，并再次请求独立审核；两次请求均到达指定内网地址，未使用云端凭据，内部统计记录 2 次，付费请求新增 0 次。另验证独立凭据、错误模型标识、缺失 usage、重定向、禁止外发的资料和错误配置。此验证覆盖协议及执行接线，未加载客户推理模型或测量其语义质量、吞吐量及部署容量。
