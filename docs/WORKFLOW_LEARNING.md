# 任务拆解、流程固化和修订经验

管理员在「工作台·任务中心 → 流程与经验」查看项目最近 50 个计划版本。版本显示步骤顺序、依赖、智能体版本、工具与技能版本、校验值和验收条件。完整历史继续保存在任务详情。相同任务的需求分析、首次计划、规划被拒和审核后重规划各有独立记录。流程和工具授权表示可以执行，实际调用以任务轨迹为准。

## 形成可复用流程

1. 自主任务按目标和资料拆解为 1 到 4 个顺序步骤。执行时检查工具目录、技能依赖和当前权限。系统保存计划、当前输入版本和执行快照。
2. 通过独立审核且无硬性失败的自主任务可形成流程候选。候选仅携带通用职责和冻结的工具、技能及执行配置，不包含来源文本、数值或任务专用说明。
3. 在「评测与入库」选择来源候选、至少两个独立样本和总预算。使用开发样本与单独的留出样本，在相同输入上重新执行基线和候选。检查样本相互独立、候选全部通过审核、费用已结算、整体费用回归有界，并确有质量改善或成本下降。通过后发布工作流及其智能体版本。
4. 新任务会将当前目标、质量配置和输入格式与已评测流程比较。相同目标与格式可直接冻结该流程的节点、智能体和工具版本并运行。输入内容仍只取自新任务的授权来源。存在多份匹配时先考虑最近创建的有效候选。目标不同则回到正常规划，可按需要组合有效的已评测智能体。
5. 读取候选来源、评测样本和依赖发布状态，检查撤回、过期、版本漂移、工作流或智能体停用。失效的发布不进入自动选择；若在规划中途失效，拒绝冻结该次计划。复用记录保留原发布 ID、版本、校验值和评测 ID。每次复用结果仍须按本次任务独立审核。

## 质量和长期经验

任务的确定性检查覆盖适用的产物结构、可定位引用、来源和任务专用规则。对于自主分析正文中的明确加减复算断言，按十进制重新计算，例如“复算：4+3=6”将触发硬性失败并给出正确值。仅支持标注为复算、合计或核对且占完整一行的单个数值等式，引用、近似值和一般自然语言不据此判分。独立模型在单独上下文评审需求覆盖，不能豁免确定性检查失败。这些检查不证明回答的所有事实都成立。

失败可导致有界的针对性重规划。经验须来自已记录的失败检查、确有变化的前后计划和通过的复核。平台只保留已知检查类别、失败项数量变化以及经授权的工具变化。候选通过独立评测并晋升后，这些通用经验可以作为相同资料模态与媒体类型的后续规划提示；不传递历史任务内容或答案。无修订、只重试或复核仍失败时不会生成成功经验。资料撤回或原发布变化后停止引用旧经验。

## 接口和验证

管理接口要求管理员、项目操作员或只读观察员身份，并核对项目成员关系：

- `GET /api/v2/workflow-learning?project_id=…` 查看当前项目最近计划与已发布流程。
- `GET /api/v2/workflow-learning/plans/{plan_id}` 查看拆解、组成版本和输入指纹。步骤原文及验收要求仅对管理员或任务所有者展示。
- `GET /api/v2/workflow-learning/publications/{candidate_id}` 查看当前可用的发布、冻结步骤、评测检查和修订经验。
- 评测使用现有 `/api/v2/agent-candidates` 路由和统一预算网关。

`backend/tests/test_workflow_learning.py` 使用隔离业务库、合成账本、明确的模型替身和真实 Worker。测试包括完整四臂重放后晋升、匹配任务复用、历史样本删除后回到新规划、跨项目拒绝、过滤无效经验，以及独立模型无法豁免明确的复算错误。生产硬件吞吐和模型回答准确率需另外测量。
