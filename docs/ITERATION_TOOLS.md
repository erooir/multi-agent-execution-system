# 本轮交付：稳定链路与真实工具型 Agent

本轮在当前 main 工作区实施，未读取旧 demo、旧提交或其他分支。运行数据、费用账本、截图和详细验收报告留在忽略的 `.local/`，不进入源码。

## 修复依据与结果

| 原问题 | 本轮处理 |
| --- | --- |
| 模式与资料不匹配，提交后才失败 | 后端预检查与受理共用逻辑；界面按能力目录联动，匹配模式、模态、版本与工具授权 |
| 连接错误被误报成输出格式错误 | 网关显式使用系统代理，检查 SDK 运行状态，分开记录网络、鉴权、预算、截断、格式与服务错误 |
| 失败后难以重新提交 | 保留表单；复制任务产生新幂等键；详情状态及时同步列表，旧轮询不能覆盖新状态 |
| 仅最后一个输出完整评审 | 所有交付产物逐项检查并独立评审，汇总质量；硬失败产物不发布 |
| 修订缺少具体依据 | 传递原始评审问题和修改建议，最多两轮；不同轮次节点独立显示 |
| 普通文本生成无法自主使用能力 | 正式任务接通 Agno Agent 工具循环，所有轮次经过网关和持久预算 |
| 真实验收中发现引用扩展字段及非规范 JSON | 增加 Pydantic 输出契约与模型 JSON 模式；不发布附加的未校验字段，仍严格校验证据 |
| 真实验收中发现组合筛选排序漏掉排序 | 修复先筛选后排序；向模型公开参数枚举和独立调用语义；真实 MCP 回归覆盖此例 |
| 模型偶发引用字段或评审结构错误 | 评审使用Pydantic输出契约及明确允许的来源ID；引用类型接受kind/type，原文source类别规范为source_span；格式错误携具体字段问题进入有限修订，原始响应只存私有诊断，证据真实性仍逐项校验 |
| 冷启动时身份库初始化偶发锁冲突 | 仅对SQLite初始化锁冲突进行有时限重试，不重置账号或历史记录 |
| 撤回后事件中仍可能含计算摘要 | 任务详情、分页事件和SSE统一隐藏派生摘要；SDK日志仅保留级别信息，避免校验异常输出资料 |
| MCP断连后异常保存失败 | 异步调用失败时不保存协程对象，仅保存可序列化结果；真实MCP会话关闭后的再次调用验证为明确失败 |

## 现在怎样使用

1. 登记或上传 UTF-8 文本、JSON、CSV，填写来源及授权说明。只有明确允许外发的资料才能标为公开。
2. 新建任务选择“文本分析”或“来源文本整理”，执行模式选择“云端模型”，流程保持“自动匹配能力与流程”。默认每任务1元、300秒、一次质量修订；可配置最多两轮。
3. 直接描述目标，例如“提取负责人并提供原文依据”“按部门汇总金额”“筛选A组并按金额降序”。Agent 自主决定使用工具、MCP 和技能的步骤。
4. 默认只读所选资料。开启“使用项目公开知识”后，额外冻结同项目有效公开文本/表格范围（总数最多50份），不能跨项目。
5. 任务详情的“工具与技能”和节点/实例详情提供调用版本、耗时、错误与证据；“查看输入与输出”读取实际参数和结果，仍受项目权限和来源撤回约束。

本地模式继续执行确定性工具，不宣称有模型语义理解。结构化数据整理任务仅支持本地/演练；需要模型自主选择操作的表格任务使用“文本分析＋云端”。

已有流程锁定原 Agent 版本，不自动改绑。需要工具型能力时使用自动匹配，或编辑并发布新流程。已有自建 Agent 可在草稿选择“自主工具型 Agent”，绑定工具与技能后发布。

## 已接入的真实能力

- 内置 tools：资料目录、分页读取、精确关键词检索、逐字证据定位。
- MCP：官方 `mcp` SDK 的真实 stdio 客户端/独立服务，执行表格筛选、排序、去重、计数、求和、平均值、最小/最大值及分组。最多10000行、2MB输入；预览截断明确标注，统计处理完整匹配集合。
- skills：`evidence-analysis`、`table-analysis` 的真实 SKILL.md 与 references。通过 Agno LocalSkills 校验加载，按需读取；不暴露脚本执行工具。

工具、MCP 实现和技能按版本及校验和绑定。执行时实现不匹配会拒绝调用，需发布新 Agent 版本；历史版本与已完成结果保留。部署升级需在无运行中任务时协调 API/Worker，并运行版本升级命令。

## 运行与验收

```powershell
uv sync --frozen --python 3.12
.venv/Scripts/python.exe -m scripts.export_contracts
npm --prefix frontend ci
npm --prefix frontend run generate:types
npm --prefix frontend run build
.venv/Scripts/python.exe -m scripts.enable_agent_tools
./scripts/start.ps1 -SkipBuild
```

`enable_agent_tools` 仅升级未自定义的内置公开模板，重复执行不产生相同版本；新项目直接建立工具型文本模板。修改过指令或参数的模板交由用户编辑发布。

真实验收受 `.local/development-test.sqlite3` 的10元上限及原 `.local/budget.sqlite3` 的300元上限共同约束。初始化开发账本时纳入当前已有保守占用，不重置原账本；未决费用不释放。备份恢复合并两个账本的历史，不回退后续费用。

## 接口与扩展约束

新增 `/api/v2/capabilities?project_id=...`、`POST /tasks/preflight`、`POST /model/connectivity`、`GET /tasks/{id}/tool-calls` 和单次调用详情。均沿用项目权限；连通性检查只发不带密钥的 HEAD，不产生模型费用，也不证明当前密钥有效。

AgentInput 新增 `execution_strategy`、`tool_refs`、`skill_refs`；TaskInput 新增 `use_project_knowledge`，默认关闭。旧版本默认 fixed。Pydantic 是公共契约源，导出 OpenAPI/JSON Schema 后生成 `frontend/src/generated/api.ts`，不手动修改生成文件。

新增工具须定义输入/输出契约、版本、授权、费用边界、错误及真实验收样例；处理资料经任务上下文读取，不能自行连接数据库或读取任意路径。MCP 子进程不继承模型密钥，取消或截止后完成清理再结束任务。每节点每轮最多12次工具调用，整个任务最多20次模型请求；所有写入校验任务租约令牌。

本轮没有接入公网搜索、外部业务写入、技能脚本、任意代码执行、动态创建 Agent、Word/PDF、语义多模态或新的自动晋升能力。已有本地 SQLite 运行方式保持；PostgreSQL 用于真实集成回归。本轮依赖新增后，旧离线 wheelhouse/镜像验收不能代表新版本，重新封装时须补齐依赖闭包和 skills 目录。
